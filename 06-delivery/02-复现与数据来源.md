## 二、登录流程（含验证码）

站点登录页有滑块拼图验证码，挑战接口返回结构：

```http
POST /api/branding/login/captcha
X-CSRFToken: <cookie csrftoken>
X-Requested-With: XMLHttpRequest

→ {"ticket":"<base64(payload)>:<ts>:<sig>", "background":"data:image/jpeg;base64,…",
   "piece":"data:image/webp;base64,…", "track":{"width":320,"height":104},
   "piece_box":{"width":46,"height":46,"top":29.0}, "tolerance":10}
```

`ticket` 第一段 base64 解码即得 `{"offset":260,"purpose":"login","picture":"slide-03",…}`。
把它作为 `position` 提交给 `/api/branding/login/captcha/verify` 即通过，拿到一次性 `token`，再随登录表单提交。

> **这段写在这里不是为了教人绕过，而是为了让研发能复现并验证修复**。修复后同样脚本应当失败（`captcha_invalid` 或 ticket 不透明）。

抓取方式：
1. 保存 Cookie（`sessionid` + `csrftoken`）到 `cookies.json`；
2. Playwright `addCookies` 注入，逐路由 `goto(waitUntil='networkidle')`；
3. 监听 `response`，把 `/api/*` 的 JSON 响应按 `METHOD path` 去重落盘；
4. 每页截图（`fullPage` 与视口各一份）；
5. 对弹层/抽屉额外点击（新建数据集、模型详情、标注页）。

## 六、脱敏处理清单

| 原始内容 | 处理 |
|---|---|
| `sessionid` / `csrftoken` / 验证码 token | 全部移除，不复用 |
| 拼图 ticket 的真实 payload | 替换为 `<opaque-ticket-id>` |
| OSS 预签名 URL 中的 `AWSAccessKeyId` 与 `Signature` | 移除，样例中不出现 |
| 服务器绝对路径 `/root/projects/…`、`/opt/label-studio-data/…` | 替换为 `<TRAIN_ROOT>/`、`<DATA_ROOT>/` |
| 真实邮箱（学生/员工） | 在文档中改为占位或移除 |
| 头像 URL（带 AK） | 不落盘 |

校验命令：

```bash
grep -rl "AWSAccessKeyId\|/root/\|/opt/label-studio" 07-data/samples/ || echo "clean"
```
