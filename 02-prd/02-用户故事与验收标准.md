# 用户故事与验收标准

> 格式：`作为 <角色>，我要 <能力>，以便 <价值>` + Gherkin 验收标准（Given/When/Then）。
> Epic 编号对应 `01-产品需求文档-PRD.md §3`。

## E1 口径与信任基建

### US-1.1 指标带作用域（F1.1）
**作为** 单位管理员，**我要** 每个数字都标明统计范围，**以便** 向客户汇报时不会被问"到底几个"。

```gherkin
场景: 首页指标带作用域标签
  假如 我以单位管理员身份登录
  当 我打开首页
  那么 每个指标卡都显示一个作用域 chip（本团队/本单位/全平台）
  并且 "标注项目" 卡的数值与项目列表页统计卡数值相同
  并且 两者 chip 均为 "本单位"

场景: 口径审计脚本
  当 CI 运行 metric-consistency 测试
  那么 它比对 /(home), /projects, /dashboard 三处的同名指标
  并且 任一不一致则构建失败
```

### US-1.2 错误码语义化（F1.2）
**作为** 用户，**我要** 看到"这个页面不存在"而不是"服务不可用"，**以便** 知道该找谁。

```gherkin
场景: 访问未部署的路由
  当 我访问 /projects/new
  那么 返回 HTTP 404 且响应体含 code="feature_not_deployed"
  并且 页面显示"新建项目功能未开放，请从项目列表右上角创建"
  并且 不出现裸 "Service Temporarily Unavailable"

场景: 标注服务异常
  假如 上游 Label Studio 返回 500
  当 我打开标注页
  那么 返回 HTTP 502 且 code="upstream_label_studio"
  并且 页面显示重试按钮与追踪 ID
```

### US-1.3 文档数字自生成（F1.3）
**作为** 交付经理，**我要** 手册里的数字与系统一致，**以便** 客户验收时能对上。

```gherkin
场景: 手册权限码数量
  当 我打开 /manuals/annotation 第 2 章
  那么 权限码数量显示 107（来自 /api/rbac/permissions 的 count）
  并且 页脚注明 "数据截至 <commit>"
```

## E2 任务状态机升级

### US-2.1 草稿可识别（F2.1 / F2.2）
**作为** 标注员，**我要** 平台提醒我"有草稿未提交"，**以便** 我的任务不会永远卡在标注中。

```gherkin
场景: 草稿滞留 24 小时
  假如 任务 10218 状态为 drafting 且 draft_updated_at 为 25 小时前
  当 我打开项目数据页
  那么 该行显示黄色标记 "草稿滞留"
  并且 该行排在列表前列
  并且 顶部出现提示 "你有 1 条草稿超过 24 小时未提交"

场景: 离开标注页拦截
  假如 我在标注页修改了 2 个区域但未提交
  当 我点击返回项目列表
  那么 弹出确认 "有未提交的标注：保留为草稿 / 放弃修改 / 继续编辑"
  并且 选择"保留为草稿"后任务状态变为 drafting
```

### US-2.2 进度三段式（F2.3）
**作为** 项目管理员，**我要** 一眼看出"多少通过了、多少在途"，**以便** 判断项目健康度。

```gherkin
场景: 项目卡片进度
  假如 项目有 30 个任务：passed 0，in_flight 8，unclaimed 22
  当 我查看项目卡片
  那么 进度条显示 "0% 通过率"
  并且 分段显示 绿0 / 蓝8 / 灰22
  并且 hover 显示六态明细
  并且 与统计页 "已通过 0 / 30" 一致
```

### US-2.3 打回理由结构化（F2.4）
**作为** 质检员，**我要** 用分类代替手打理由，**以便** 打回 68 条时不用重复写字。

```gherkin
场景: 打回必须选分类
  当 我点击"打回"
  那么 必须从 [框不贴边/类别错/漏标/多标/违反说明/其它] 选一项
  并且 可附加文字说明
  并且 提交后标注员看到 "打回原因：类别错（第 1 次）"

场景: 打回原因统计
  当 我打开质检视图
  那么 看到 "本项目 Top3 打回原因：漏标 42% / 类别错 31% / 框不贴边 18%"
```

## E3 安全加固

### US-3.1 验证码不可绕过（F3.1）
**作为** 平台安全负责人，**我要** 验证码答案只存在于服务端，**以便** 登录接口不能被打。

```gherkin
场景: ticket 不透明
  当 客户端请求 /api/branding/login/captcha
  那么 响应中 ticket 为 32 位十六进制随机串
  并且 base64 解码后不包含任何数字型 offset
  并且 响应中不含 tolerance 字段

场景: 校验失败即作废
  假如 我用错误 position 提交
  那么 返回 {ok:false, code:"captcha_invalid"} 并附新挑战
  并且 原 ticket 再次提交返回 captcha_expired

场景: 失败次数限制
  当 同一账号 5 次登录失败
  那么 锁定 15 分钟并返回剩余秒数
```

### US-3.2 敏感信息脱敏（F3.3）
```gherkin
场景: 接口不返回绝对路径
  当 我请求 /api/model-factory/training/resources/
  那么 任一 dataset_key 不含 "/root/" 或 "/opt/"
  并且 返回 resource_id 供前端换取短链

场景: AK 不暴露
  当 我打开任意页面
  那么 网络请求 URL 中不含 "AWSAccessKeyId"
```

### US-3.3 高风险操作二次确认（F3.4）
```gherkin
场景: 删除项目
  当 我在项目设置点击"删除项目"
  那么 要求我输入项目名 "玻璃缺陷检测Project #32"
  并且 输入不匹配时按钮禁用
  并且 完成后写入审计日志（对象、前后值、操作人）
```

## E4 产能看板与预测

### US-4.1 瓶颈可诊断（F4.1）
**作为** 平台管理员，**我要** 知道产能卡在哪个环节，**以便** 决定加人还是改流程。

```gherkin
场景: 漏斗停留时长
  当 我打开 /capacity
  那么 看到六状态漏斗及每环节 P50/P90 停留时长
  并且 系统标出瓶颈环节（如"审核中：68 条，P50 31h，P90 96h"）
  并且 给出建议 "审核环节积压，建议增加质检员或启用打回模板"

场景: 按人负载
  当 我按"手中任务数"排序
  那么 看到每人手中任务数、今日通过数、平均打回次数、平均质量分
```

### US-4.2 交付预测（F4.2）
```gherkin
场景: ETA 区间
  假如 项目剩余 100 条任务，近 7 天日均通过 5 条
  当 我查看项目统计页
  那么 显示 "预计完成 2026-12-05（乐观 11-28 / 悲观 12-18）"
  并且 显示 "若审核环节增加 1 人，可提前 6 天"
```

### US-4.3 智能派单（F4.3）
```gherkin
场景: 新任务按负载分配
  假如 张三名下 40 条未完成，李四名下 5 条
  当 管理员导入 100 条新任务并选择"智能分配"
  那么 李四分得显著更多（按 1/负载 加权）
  并且 管理员可查看分配理由并手动调整
  并且 已领取任务的归属不变（不重分配）
```

## E5 质量与一致性

### US-5.1 一致性可量化（F5.1）
**作为** 院校老师，**我要** 看到学生之间标注的一致性，**以便** 给出一致性成绩。

```gherkin
场景: 分类任务一致性
  假如 项目 maximum_annotations=3，10 个任务各 3 份标注
  当 我打开一致性看板
  那么 显示 Fleiss' κ = 0.72
  并且 显示两两一致性矩阵
  并且 标出低于整体 2σ 的标注员

场景: 检测任务一致性
  那么 以 IoU≥0.5 匹配计算一致性，并显示匹配失败示例缩略图
```

### US-5.2 批次质量报告（F5.2）
```gherkin
场景: 导出附质量摘要
  当 我在导出页勾选"附质量摘要"
  那么 导出包里多一个 quality-summary.pdf
  并且 含 漏检率 / 打回率 / 一致性 / 按人贡献
```

### US-5.3 金标准抽检（F5.3）
```gherkin
场景: 金标准不可识别
  假如 管理员标记 5% 任务为金标准
  当 标注员领取任务
  那么 界面无任何"这是金标准"的提示
  并且 通过率进入其质量分（权重可配）

场景: 金标准泄漏检查
  当 标注员请求 /api/projects/218/workflow/tasks
  那么 响应中不含 is_gold 字段
```

## E6 激励与结算透明

### US-6.1 打回即扣（F6.1）
**作为** 财务/运营，**我要** 打回当场产生成本，**以便** 标注员不会"先交再改"。

```gherkin
场景: 打回生成负流水
  假如 任务 10218 被质检员打回
  那么 立即生成一条 -2 分流水，说明"任务 #10218 一审打回"
  并且 若该任务最终通过，则流水保留（不冲销）
  并且 标注员积分页可见该条

场景: 申诉窗口
  当 打回后 7 天内标注员提交申诉且管理员撤销打回
  那么 生成 +2 冲销流水并记录审批人
```

### US-6.2 计分构成透明（F6.2）
```gherkin
场景: 展开明细
  当 我在积分流水点击某条记录
  那么 看到 "基础分 +10 / 首稿加成 +2 / 评分加成 +1（质量分 92 → A 档）/ 打回扣分 0 = +13"
```

### US-6.3 对账单（F6.3）
```gherkin
场景: 按人导出
  当 我选择"导出对账单"并按标注员分组
  那么 得到 XLSX，每人一页：任务明细、打回次数、评分、合计分值
```

## E7 模型闭环 ROI

### US-7.1 采纳率可测（F7.1）
**作为** 客户侧算法工程师，**我要** 知道模型到底省了多少人工，**以便** 决定是否续费。

```gherkin
场景: 采纳率展示
  假如 项目启用预标注模型 A，处理 100 个任务共生成 500 个预标注区域
  当 30 天后我打开模型详情
  那么 显示 采纳率 62%（310/500 未修改直接通过）
  并且 显示 修正率 28% / 删除率 10%
  并且 显示 "启用预标注后单任务人工耗时中位数 4.2 min（启用前 7.8 min）"
```

### US-7.2 难例回流（F7.2）
```gherkin
场景: 难例自动入池
  当 终审打回一条任务或标注员删除一个预标注区域
  那么 该样本进入"难例池"并标记来源（reject/deleted_prediction）
  并且 我可一键"用难例池新建训练集"
  并且 训练集页面显示 "含 124 条难例（来自 3 个项目）"
```

### US-7.3 模型对比（F7.3）
```gherkin
场景: 勾选对比
  当我 在模型超市勾选 3 个模型并点击"对比"
  那么 出现横向对比表：mAP50 / mAP50-95 / 参数量 / 权重 / 延迟 / 类别数 / 采纳率 / 下载量
  并且 最优值高亮
```

### US-7.4 灰度部署（F7.4）
```gherkin
场景: 按比例部署
  当 我把模型 A 部署到项目并设流量 20%
  那么 约 20% 的新任务由 A 预标注，其余无预标注
  并且 我可在 7 天后一键全量或回滚
```

## E8 数据集版本与血缘

### US-8.1 版本化（F8.1）
```gherkin

场景: 从模型反查数据

  那么 看到 数据集 v2 → 训练集 ts-08 → run #15 → 模型 v3 → 项目 218
  并且 每个节点可点开查看详情
```
