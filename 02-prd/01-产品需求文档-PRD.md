## 0. 一页纸摘要（给决策者）

**现状**：平台已经把"组织隔离 → 任务流转 → 审核验收 → 积分结算 → 数据集复用 → 模型训练 → 预标注"这条链跑通了，骨架专业度高于同类自研产品。但**基础规模数据暴露了真问题**：4,825 条任务里只有 1,148 条有标注（23.8%），4,157 条卡在"进行中"，交付率 3.9%。**平台不缺功能，缺的是把产能推过审核关的机制。**

**v2.x 的三条主线**：

| 主线 | 要解决的问题 | 核心交付 | 成功标准 |
|---|---|---|---|
| **A. 信任基建** | 三个页面对同一名词给三个数；错误码 503 一锅炖；文档与实现漂移 | 统一口径（`StatCard` + `scope`）、语义化错误码、文档自生成 | 口径类工单归零；直链可达率 100% |
| **B. 产能引擎** | 草稿黑洞、打回零成本、无按人积压视图、无吞吐预测 | 草稿子状态、打回即扣、产能看板（按人/按环节/ETA）、智能派单 | 交付率 3.9% → 25%；平均任务周期 −40% |
| **C. 闭环补齐** | 模型上线后无 ROI 证据；难例不回流；数据集无版本 | 预标注采纳率、难例回流、数据集版本与血缘、模型对比 | 模型 → 产能可度量；复用率提升 |

**不做**（明确排除）：移动端标注画布、通用 MLOps 平台、众包抢单大厅、多语言 UI。

## 1. 背景与目标

### 1.1 背景

数据标注行业的竞争点已经从"能不能标"转向"标完之后说得清吗"。当前平台在**流程可追溯**上做到位（三级流转、打回计数、验收台账），但在三处失守：

1. **可信度**：数字口径不一致 + 文档漂移 + 大量 503 端点 → 客户不敢拿它做验收依据。
2. **产能**：任务状态机把"存草稿"与"正在标"混为一谈，打回不产生即时成本，导致质量前置失效、审核环节积压。
3. **闭环**：模型训练完进"私有货架"，但**没有任何指标证明"用了模型省了多少人"**，模型工厂沦为展示货架。

### 1.2 目标（OKR 形式）

**O1：让客户敢用平台数据对外汇报**
- KR1 全站同名指标口径一致率 100%（口径审计脚本可验证）
- KR2 SPA 直链可达率 100%，错误页可按 code 区分（404/403/502/503）
- KR3 内置手册关键数字与接口一致率 100%（页面动态读取）

**O2：把产能推过审核关**
- KR1 项目交付率（已通过/总任务）从 3.9% → 25%
- KR2 "进行中 > 48h 且无草稿"的任务占比 < 5%
- KR3 平均任务周期（领取 → 终审通过）中位数 ≤ 24h

**O3：让模型的价值可被度量**
- KR1 使用预标注的项目，单任务人工耗时下降 ≥ 30%（对照测试）
- KR2 模型详情页出现"近 30 天预标注采纳率"字段的项目覆盖率 100%
- KR3 每月至少 20% 的难例回流进训练集

### 1.3 非目标

- 不做移动端标注画布（画框/画笔需要精确输入，移动端只做审核/验收）。
- 不做通用 MLOps（实验追踪、超参搜索留给外部工具，平台只承接"标注 → 训练 → 预标注"这一段）。
- 不做众包抢单（破坏"打回后归属不变"的设计前提）。

## 2. 用户与角色

详见 `01-analysis/04-用户画像与关键旅程.md`。此处只定义**权限与产品行为边界**：

| 角色 | 作用域 | 能做的 | 不能做的（产品强制） |
|---|---|---|---|
| 平台管理员 `SYS_ADMIN` | 全平台 | 数据大屏、超管设置、单位管理、角色模板 | 不能替单位管理员配 OSS 密钥（需单位自己填） |
| 单位管理员 `INST_ADMIN` | 本单位 | 团队/成员/云存储/模型配置/首页装扮/审批 | 看不到其它单位任何数据 |
| 团队所有者/管理员 `OW`/`AD` | 团队 | 空间管理、团队角色、数据集分发 | 不能改平台级设置 |
| 空间管理员 `WS_ADMIN` | 空间 | 空间内项目与成员 | 不能跨空间 |
| 项目管理员 | 项目 | 设置、发布、导出、分派 | 不能改标注模式（建后不可改） |
| 质检员 `PR_REVIEWER` | 项目 | 通过/打回（一审） | 不能终审 |
| 验收员 `PR_VALIDATOR` | 项目 | 终审、评分 | 不能取消已发积分（只能补差额） |
| 标注员 `PR_ANNOTATOR` | 项目 | 领取、标注、提交 | 不能看他人标注（除多人同标对比页） |

**硬规则**（沿用现有且必须保留）：
1. 只能授予**等级更低**的角色（`rank` 数字更大）。
2. 不能变更自己的角色。
3. 权限码三态中**「拒绝」优先**于「允许」。

## 4. 功能需求详述

### E1 口径与信任基建（P0 / v2.1）

#### F1.1 全局指标口径统一

**问题**：首页 80 / 项目页 47 / 大屏 95；卡片 0% vs 统计页 3.33%。

**需求**
1. 定义 `MetricScope` 枚举：`SELF`(个人) / `TEAM`(当前团队) / `INSTITUTION`(本单位) / `PLATFORM`(全平台)。
2. 所有数字型指标组件必须声明 `scope`，UI 上以 chip 显示（`本团队` / `本单位` / `全平台`）。
3. 建立**指标字典**（单一事实来源）：每个指标一个 key，后端 `/api/metrics/definitions` 返回 `{key, name, scope, formula, source}`。
4. 「已标注」与「已通过」分离为两个独立术语，全局禁用"完成/已完成"这类含糊词，统一为：
   - `已标注` = 有至少一条 annotation（含草稿）
   - `已通过` = 终审通过（`pipeline.passed`）
   - `交付率` = `passed / total`

**验收**
- 同一指标在任意两个页面数值相同（自动化脚本比 3 个页面）。
- 每个数字卡可见 scope chip。
- 术语表在 `/manuals/glossary` 可查。

#### F1.2 语义化错误码

**问题**：路由不存在、服务异常、功能未部署都返回 503。

**需求**
| HTTP | code | 前端表现 |
|---|---|---|
| 404 | `route_not_found` | "页面不存在" + 返回首页 |
| 403 | `permission_denied` | "需要 `projects.create` 权限" + 申请入口 |
| 404 | `resource_not_found` | "项目不存在或已删除" |
| 502 | `upstream_label_studio` | "标注服务暂时不可用" + 重试 + 反馈 |
| 503 | `feature_not_deployed` | 入口**不展示**（feature flag），若直接访问则"功能未开放" |

**验收**
- `/datasets/new` 等 4 个实测 503 路由，改为正常渲染或明确"未开放"。
- 错误页展示 `code` + 追踪 ID（便于客服对齐日志）。

#### F1.3 文档自生成

**需求**：内置手册中的数字（权限码数量/分类节点数/模型数/支持格式）由构建期脚本从代码读取并注入，禁止手写。

**验收**：手册页显示"数据截至 <commit> · <时间>"；CI 校验：若手册数字与接口不一致则构建失败。

#### F1.4 空状态与加载态规范

**需求**：统一"图标 + 一句解释 + 一个主行动"三件套；所有列表加载 > 400ms 显示骨架屏。

### E2 任务状态机升级（P0 / v2.1）

#### F2.1 拆分子状态

**现状**：`annotating` 同时表示"已领取未保存"和"已存草稿未提交"，7/30 任务卡在此状态且无提醒。

**新状态机**
```
unclaimed ──领取──▶ working（已领取，无草稿）
working ──保存草稿──▶ drafting（有草稿，未提交）
drafting ──提交──▶ pending_review
working/drafting ──释放──▶ unclaimed（不增加打回次数）
pending_review ──一审通过──▶ pending_validation ──终审通过──▶ passed
pending_review/pending_validation ──打回──▶ rejected ──修改提交──▶ pending_review
```

**字段变更**
- `Task.status` 增加 `working` / `drafting`（原 `annotating` 拆二）。
- `Task.draft_updated_at`（草稿最后保存时间）。
- `Task.draft_age_hours`（计算字段，供看板）。

**验收**
- 数据页可按 `drafting` 单独筛选。
- 卡片上"标注中"显示为"标注中（含 N 条草稿）"。

#### F2.2 草稿滞留提醒

**需求**
1. 任务 `drafting` 且 `draft_age_hours > 24` → 数据页黄色标记 + 排序前置。
2. 每日 09:00 汇总该标注员的滞留草稿数，站内通知 + 邮件（可关）。
3. 标注页离开拦截：有未提交变更时弹确认（"保留为草稿 / 放弃 / 继续编辑"）。

**验收**：新建 1 条草稿，24h 后（可用时间加速测试）出现标记与通知。

#### F2.3 项目进度三段式

**需求**：项目卡片进度条改为三段色（已通过 绿 / 在途 蓝 / 未开始 灰），百分比只按 `passed/total` 计算并标注"通过率"；hover 展示六态明细。

**验收**：卡片与统计页数字一致；hover 明细可键盘访问。

#### F2.4 打回理由结构化

**需求**
1. 打回时必须选**理由分类**（框不贴边 / 类别错 / 漏标 / 多标 / 违反说明 / 其它），并附文字。
2. 理由分类统计进入质检员视图（"本项目 Top3 打回原因"）。
3. 标注员在任务详情看到上一轮打回分类 + 理由 + 上一版标注的**叠加对比**（半透明）。

**验收**：打回后标注员打开任务，可见"打回原因：类别错（第 1 次）"及对比视图。

### E3 安全加固（P0 / v2.1）

#### F3.1 验证码服务端化

**现状**：`offset` 明文在 ticket 的 base64 载荷中，脚本可 100% 通过。

**需求**
1. `ticket` 改为不透明随机 ID（32 hex），服务端存储 `{ticket_id: {offset, purpose, expires_at, attempts}}`（Redis / DB）。
2. 响应中移除 `tolerance`；容差服务端常量。
3. 同一 ticket 校验失败即作废并下发新挑战（现有前端行为已支持，保留）。
4. 校验成功后 token 一次性使用，绑定 `purpose` 与 IP 段。

**验收**：解码 ticket 得不到 offset；离线脚本无法在不识图情况下通过；同一 token 二次使用被拒。

#### F3.2 登录风控

**需求**
1. 同 IP+账号 5 次失败 → 锁定 15 分钟，返回剩余时间。
2. 超管与单位管理员强制 TOTP（可在超管设置里按单位开关）。
3. 新设备/新 IP 登录邮件提醒。
4. 会话列表可见 + 可远程登出。

#### F3.3 敏感信息脱敏

**需求**：接口不返回服务器绝对路径（`/root/...`、`/opt/...`）、OSS AK ID；统一返回资源 ID，前端按需换取预签名短链（≤5 分钟）。

**验收**：全站接口响应扫一遍，无 `root/`、`opt/`、`AWSAccessKeyId` 字样。

#### F3.4 管理操作二次确认

**需求**：删除项目 / 删除数据集 / 停用单位 / 调整配额 / 重置缓存 → 输入对象名称确认 + 记录审计。

### E4 产能看板与预测（P1 / v2.2）

#### F4.1 产能看板（新页面 `/capacity`）

**需求**：一屏回答"产能卡在哪"。

| 区块 | 内容 |
|---|---|
| 漏斗 | 六状态横条 + 每环节平均停留时长（P50/P90） |
| 按人 | 每人：手中任务数、今日通过数、平均打回次数、平均质量分（可排序） |
| 瓶颈诊断 | 自动标注"瓶颈环节"（停留时长增长最快的环节）+ 建议 |
| 趋势 | 近 14 天通过量 vs 新增量（净积压） |

**验收**：能看到"审核中 68 条，平均停留 31h（P90 96h）"这类可行动结论。

#### F4.2 交付预测 ETA

**需求**：基于近 7 天各环节吞吐（移动平均），预测项目完成日期，给区间（乐观/中性/悲观），并明示"若瓶颈环节增加 1 人，可提前 N 天"。

#### F4.3 智能派单

**需求**：在保持"任务归属人固定"的前提下，**新增任务**按（当前负载 + 历史该类别质量分 + 打回率）加权分配；管理员可手动推翻。

#### F4.4 批量操作增强

**需求**：数据页支持"批量重新分配 / 批量重置 / 批量加入训练集 / 批量导出选中"，并给操作预检（影响 N 条，其中 M 条有标注将被清空 → 需输入确认）。

### E5 质量与一致性（P1 / v2.2）

#### F5.1 一致性看板（多人同标场景）

**需求**：对 `maximum_annotations > 1` 的项目，计算：
- 分类任务：Cohen's κ / Fleiss' κ
- 检测任务：按 IoU 0.5 匹配的 mAP-like 一致性
- 分割任务：mIoU
- 文本任务：编辑距离归一化一致度

展示：整体一致性、按标注员两两一致性矩阵、离群标注员识别（低于整体 2σ）。

#### F5.2 批次质量报告

**需求**：导出时可选"附质量摘要页"（PDF/CSV）：漏检率、过杀率（若有金标准）、打回率、一致性、按人贡献。用于对客户交付。

#### F5.3 金标准抽检

**需求**：管理员可把 5% 任务标记为"金标准"（已有正确答案），标注员不知情；金标准通过率进入其质量分（权重可配）。

---

### E6 激励与结算透明（P1 / v2.2）

#### F6.1 打回即扣

**需求**：打回时立即生成一条负数流水（可回滚），而非等到最终通过。任务最终未通过时该扣分保留。

**理由**：消除"先交再改"的最优策略。

#### F6.2 计分明细可见

**需求**：积分流水每条可展开，显示构成：
```
任务 #10218 · 通过
基础分 +10 · 首稿加成 +2 · 评分加成 +1（质量分 92 → 档位 A）
打回扣分 0（打回 0 次）
= +13
```

#### F6.3 对账单导出

**需求**：按人 / 按项目 / 按时间段导出对账单（CSV+XLSX），含任务明细、打回次数、评分、结算金额（若配置单价）。

---

### E7 模型闭环 ROI（P1 / v2.2）

#### F7.1 预标注采纳率

**需求**：项目启用预标注后，统计：
- 采纳率 = 未被修改直接通过的预标注区域 / 全部预标注区域
- 修正率、删除率
- 单任务人工耗时对比（有/无预标注，A/B）

#### F7.2 难例回流

**需求**：终审打回或标注员删除预标注的区域 → 自动进入"难例池"；可一键生成训练集（带来源标签），进入模型训练。

#### F7.3 模型对比视图

**需求**：模型超市支持勾选 2–4 个模型横向对比（mAP50、mAP50-95、参数量、权重大小、推理延迟、类别数、训练数据、本平台采纳率、下载量）。

#### F7.4 部署与回滚

**需求**：部署到项目时可指定流量比例（如 20% 任务用模型 A 预标注），支持 A/B 与一键回滚。

### E8 数据集版本与血缘（P2 / v3.0）

**需求**
1. 数据集支持版本（`v1, v2…`），每次追加/删除文件生成新版本，旧版本可引用。
2. 血缘图：`数据集版本 → 训练集 → 训练任务 → 模型版本 → 部署项目`，任一节点可点开查看上下游。
3. 项目引用数据集时锁定版本（可选跟随最新）。

**验收**：给定一个模型，能回答"它用了哪版数据、由谁标的、经过几次打回"。

### E9 院校实训产品化（P2 / v3.0）

**需求**
1. 班级/小组维度（学生分组，任务按组分配）。
2. 成绩单导出：一致性分、金标准通过率、平均质量分、完成率，映射为百分制。
3. 教师视图：学生进度热力图、Top 错误类型。
4. 实训模板库（按课程：目标检测入门 / 语义分割 / 语音转写）。

### E10 审计全覆盖（P1 / v2.2）

**需求**：审计事件覆盖全部**资产类**对象：数据集（创建/上传/删除/分发/版本）、项目（创建/配置变更/发布/删除）、模型（训练/部署/下架）、成员（邀请/移除/角色变更）、配额（调整）、密钥（配置/轮换）。

展示：时间线 + 对象维度聚合 + 前后值 diff。

**验收**：删除一个数据集后，可在审计里查到操作人、时间、被删文件名列表。

## 5. 交互与界面要求

### 5.1 视觉一致性（详见 `03-design/01-设计系统.md`）
1. 三套视觉语言（外壳浅蓝 / 标注页沙色 / 大屏深蓝）收敛为**一套 token + 两个主题**：`theme-light`（外壳与标注页）与 `theme-dark`（大屏）。
2. 标注页保留 Label Studio 的画布行为（`shift+1` 适应窗口、`Ctrl+滚轮` 缩放、快捷键标签），但**外壳、按钮、面板配色统一**。
3. 统一圆角 `8px`（卡片）/ `10px`（按钮）/ `999px`（chip）；阴影两级；间距 4 的倍数。

### 5.2 关键页面改造清单

| 页面 | 改造点 |
|---|---|
| 首页 | 数字卡加 scope chip；"创建项目"改主 CTA 并带三步预告 |
| 项目列表 | 卡片紧凑化（默认 3 行），进度三段式，hover 展开六态 |
| 项目工作台 | 当前身份切换做成 segmented control（已有）+ 身份说明一句话（已有，保留） |
| 数据页 | 增加 `drafting` 筛选与黄色滞留标记；批量操作加预检弹层 |
| 标注工作台 | 统一顶栏（面包屑 + 提交）；离开拦截；右侧面板加"打回历史" |
| 导出页 | 附质量摘要开关；导出格式旁解释"为什么只有这几个" |
| 模型超市 | 勾选对比；卡片增加"本平台采纳率" |
| 大屏 | 与浅色主题共享 token，仅换色板 |
| 组织管理 | 表格一行一信息；配额条常显 |

### 5.3 无障碍与键盘

- 全部交互可键盘完成；焦点环可见（2px，`--focus`）。
- 对比度 ≥ 4.5:1（当前浅蓝小字在 `#F3F8FF` 上仅约 3.2:1，需加深）。
- 表格支持 `j/k` 上下、`Enter` 打开。

## 7. 数据埋点与指标定义

### 7.1 北极星指标
**周交付任务数（passed per week）** —— 它同时代表产能与质量（只有终审通过才计入）。

### 7.2 关键指标

| 指标 | 定义 | 当前基线 | v2.2 目标 |
|---|---|---|---|
| 交付率 | passed / total | 3.9% | 25% |
| 平均任务周期 | 领取 → passed 中位数 | 未度量（估 > 72h） | ≤ 24h |
| 打回率 | rejected / submitted | 未度量（≈8%） | ≤ 5% |
| 草稿滞留率 | drafting > 24h / drafting | 未度量（≈23%） | ≤ 5% |
| 预标注采纳率 | 未修改通过的预标注区域 / 全部 | 未度量 | ≥ 60% |
| 单任务人工耗时 | 标注页活跃时长中位数 | 未度量 | −30%（有预标注） |
| 口径一致性 | 三页比对一致 | 0/4 项 | 4/4 |
