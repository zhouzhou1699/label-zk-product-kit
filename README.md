## 一分钟看懂这个仓库

**被拆解的产品是什么**：一个以「单位 → 团队 → 空间 → 项目」四层隔离为骨架的多模态数据标注平台。技术上它是 **Label Studio OS 1.24.0.dev0（Community）的深度二次开发**，在外围自研了组织 RBAC、三级流转工作流、积分/证书激励、模型工厂（超市/训练/行业应用）。

**它跑通了什么**：`数据集 → 建项目 → 导入 → 发布（四项前置检查）→ 标注 → 一审 → 终审（唯一结算点）→ 积分/证书 → 导出 → 训练集 → 模型 → 预标注` 的完整闭环。

**它的真问题**：骨架专业、细节失守。4,825 条任务里只有 1,148 条有标注（23.8%），4,157 条卡在"进行中"，**交付率 3.9%**。同名指标在三个页面给三个数（80 / 47 / 95），登录验证码可被脚本解码绕过，`/datasets/new` 这类直链直接 503。

**本交付包给出什么**：不是"再写一遍它的功能"，而是**一份可执行的 v2.1 / v2.2 / v3.0 重构方案**——修信任、补产能、闭模型 ROI，每一条都带验收标准，并配了可点的原型与逐屏走查标注图。

## 核心结论（5 条）

1. **它不是标注工具，是"标注产能的中台"。** 开源 Label Studio 有画框引擎，没有多租户、三级流转、积分结算、模型市场——这四层才是它的商业价值。
2. **最好的三处设计**：发布前四项检查（把失败前置成清单）、项目页签即流程（1→2→3→4 带序号）、"为什么模型是灰的"（禁用必写原因）。三处都该制度化。
3. **最该修的三处**：① 拼图验证码答案明文下发（P0 安全）；② 同名指标三种口径（P1 信任）；③ 草稿黑洞导致 23% 任务卡在"标注中"（P1 产能）。
4. **闭环缺最后一跳**：模型上线后没有"预标注采纳率 / 单任务人工耗时"这类 ROI 证据，模型工厂沦为展示货架。
5. **重构优先级**：先信任（v2.1）→ 再产能（v2.2）→ 后资产化（v3.0）。不要先加功能。
