# 用户画像与关键旅程

## 一、五个画像（都来自平台真实数据）

### 画像 1 · 刘成龙｜平台管理员（超管）
- **身份**：光线科技有限公司（山东）· admin@qq.com
- **数据特征**：持有 4 个身份（项目验收员/质检员/标注员/管理员），今日 403 积分，31 个通过任务 —— **既管平台又亲自干活**，这是早期产品的典型状态。
- **一天**：早上看数据大屏（交付率 3.9%，红）→ 处理申请审批（127 条积压，97 条已驳回）→ 配登录页品牌 → 下午自己去标 30 条任务。
- **痛点**：
  - "我不知道这 4,157 条进行中卡在谁手里"（缺按人的积压视图）
  - "首页 80 个项目，项目页 47 个，客户问我到底几个"（口径）
  - "改个配额要点三层菜单"
- **他要的**：一个能回答"产能卡在哪"的看板，而不是六个总量数字。

### 画像 2 · 王质检｜项目质检员（一审）
- **身份**：单位内的资深标注员转岗，同时是 3 个项目的质检员。
- **一天**：进任务管理器 → 切「项目质检员」身份 → 待审核 68 条 → 逐条看标注、通过或打回、写理由。
- **痛点**：
  - 打回理由要手打，重复率高（"框没贴边"写了 200 遍）
  - 打回后任务回到"待处理"，但**看不到是谁改的、改了什么**（缺 diff）
  - 打回成本为零 → 上游质量差 → 他的工作量被动放大
- **他要的**：打回理由模板 + 前后对比视图 + 打回统计反哺培训。

### 画像 3 · 小李｜标注员（外包/兼职）
- **身份**：团队空间成员，只在一个项目里标注，按件计分。
- **一天**：进项目 → 任务管理器 → 领取 → 标注 → 提交。看积分页确认到账。
- **痛点**：
  - 提交后不知道结果，被打回时才收到（无预期管理）
  - "我更新了但没提交，任务卡住了"（他自己也不知道）
  - 积分页只给总数，不知道"这 13 分是哪个任务给的、为什么只有 13 分"（其实流水有，但没解释加成构成）
- **他要的**：明确的状态反馈 + 透明的计分过程（"这条：基础 10 + 首稿 2 + 评分加成 1"）。

### 画像 4 · 张老师｜院校实训管理员
- **身份**：山东外国语大学，带 40 个学生做实训。
- **一天**：建实训项目（多人同标）→ 学生各自标 → 他看「多人同标 · 任务示例」对比一致性。
- **痛点**：
  - 实训模式不计积分，但学生要"成绩"，平台只给"平均质量分"，没有班级维度
  - 40 人一个空间，任务分配靠手动
- **他要的**：班级/小组维度 + 一致性分数 + 可导出的成绩单（现在是导验收台账 CSV，字段不够）。

### 画像 5 · 陈工｜客户侧算法工程师（模型使用方）
- **身份**：制造企业，接平台训练出的模型上线到产线。
- **一天**：模型超市选型 → 看基准报告（mAP50 88.4%、参数 2.59M、权重 5.2MB）→ 下载权重 or 部署到项目。
- **痛点**：
  - 详情页给的是"训练时指标"，没有"在**我的**产线数据上的表现"
  - 想对比 3 个模型，只能一个个开抽屉记数字（无对比视图）
  - 部署后没有回流：线上误检的样本怎么回到平台再训？（闭环缺最后一跳）
- **他要的**：横向对比表 + A/B 部署 + 难例回流。

## 二、三条关键旅程（含情绪曲线）

### 旅程 A · 新客户从 0 到第一条验收通过（Happy Path）

| # | 步骤 | 触点 | 情绪 | 摩擦点 |
|---|---|---|---|---|
| 1 | 收到邀请链接 → 打开 | 登录页 | 🙂 惊艳（视觉强） | 拼图验证码一次过不了会烦 |
| 2 | 注册 → 等审批 | 申请审批 | 😐 等待 | **不知道要等多久**，无状态查询 |
| 3 | 管理员通过 → 进首页 | 首页 | 🙂 | 欢迎语是单位的，不是"你的第一个项目" |
| 4 | 建数据集 → 上传 30 张图 | 数据集弹层 | 😐 | 分类必选，47 个分类要滚很久 |
| 5 | 建项目 → 选模板 → 配标签 | 新建项目向导 | 😣 | 三步向导 + label_config 概念，非技术用户会卡 |
| 6 | 导入数据 → 生成 30 任务 | 已导入数据 | 🙂 | 批量导入反馈清楚 |
| 7 | 设三角色 → 发布 | 角色设置/发布 | 🙂 | **四项检查是全站最好的设计**，一眼知道差什么 |
| 8 | 标注 1 条 → 提交 | 标注工作台 | 😊 顺手 | 快捷键、撤销、区域面板都专业 |
| 9 | 质检通过 → 验收通过（评分 90） | 验收页签 | 🙂 | 评分与结论的关系没解释（评分影响钱） |
| 10 | 看积分 +3 | 积分页 | 😐 | 只看到"+3"，不知道 3 怎么来的 |
| 11 | 导出 JSON | 导出页 | 🙂 | 格式按配置动态过滤，很聪明 |
| 12 | 训练集 → 新建训练 → 等 40 秒 | 模型训练 | 😊 酷（实时曲线） | 训练完去哪？要靠"自动进私有货架"这句话 |

**关键洞察**：这条路径的**设计质量高于同类产品**（发布四检查、动态导出格式、实时训练曲线），但**第 2、5、10 步**的情绪洼地都源于同一个问题——**缺少"下一步是什么"的引导**。

### 旅程 B · 被打回后重做（Sad Path，最需要打磨）

```
提交 → 待审核 → 打回（无理由模板，理由手打）→ 任务回"待处理"
     → 标注员在"待处理"里找到 → 打开 → 不知道上一版哪里错了
     → 只能自己重新看一遍 → 修改 → 再提交 → reject_count=1（看不到这个数）
```

**缺失的三样东西**：① 打回理由的结构化展示（现在在哪个字段？）；② 上一轮标注的叠加对比；③ 打回次数对积分的可见影响（"再打回一次扣 2 分"）。

### 旅程 C · 管理员排查"数据怎么没了"

```
发现某数据集消失 → 组织管理（找团队）→ 团队详情（找成员）→ 怀疑误删
  → 想查审计日志 → 系统管理 → RBAC 页有「审计日志」页签 → 只看到角色变更
  → 数据集的删除/分发记录查不到
```

**洞察**：`audit.view` 权限存在，但审计覆盖面对不上"数据资产"这类对象。**"可追溯"是它对外讲的核心价值，但审计链在数据侧是断的**——这是产品叙事与实现的落差，比缺功能更危险。

## 三、Jobs To Be Done

| 场景 | 用户想完成的 Job | 当前满足度 | 缺口 |
|---|---|---|---|
| 生产 | 当我有 5000 张图要标时，我想知道**多久能交付**，以便安排产线 | 40% | 缺"按人/按环节的吞吐与预测" |
| 质量 | 当我要向客户证明数据合格时，我想一键导出**质量报告** | 60% | 有台账 CSV，缺一致性指标与摘要页 |
| 结算 | 当我按件付钱给标注团队时，我要**可对账的流水** | 85% | 流水完整，缺"按人/按项目导出对账单" |
| 复用 | 当新项目要用旧数据时，我不想重复上传 | 90% | 数据集引用已通，缺版本管理 |
| 选型 | 当我要选模型时，我想对比 3 个候选 | 50% | 只能逐个看抽屉 |
| 合规 | 当审计问"这条数据谁动过"时，我要完整链路 | 30% | 审计只覆盖角色/成员类对象 |
